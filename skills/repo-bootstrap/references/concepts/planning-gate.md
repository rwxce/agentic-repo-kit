# A planning gate before code

**Origin: proven.** Enforced in the production project this kit was distilled from (generalized, project names removed).

## Problem

Agents start editing as soon as they understand a request, so side effects, existing behaviour and unverified assumptions surface after the code is written. Multi-PR initiatives lose their decisions between sessions, and plan documents outlive the work.

## Principle

A feature request is detected and routed to a planning protocol before any edit: size the work, sweep who reads what will change, check the official docs, separate evidence from assumptions, and wait for an explicit "go". Plans spanning PRs live in a folder with a decision log, and the last PR deletes the folder.

## When it applies

- Repos with more than one domain or any sensitive domain, worked on by agents.

## When it doesn't

- One-off fixes, copy tweaks and questions.

## Typical mistakes

- Keyword intent detection treated as authoritative (it has false positives).
- Plans that re-list already-done work.
- Plan folders never closed.

## The check that verifies it

A prompt hook that flags feature intent and points to the planning skill; a CI gate that matches a `Closes-plan` marker with the folder deletion; a stale-plan check.

## Canonical source

- [Claude Code Docs: Best practices (explore, plan, then code)](https://code.claude.com/docs/en/best-practices)

## Variants per stack

- **Claude Code:** `UserPromptSubmit` hook plus a `plan-feature` skill; plan mode.
- **Cursor / Codex / OpenCode:** the same skill generated by rulesync; prose rule where hooks are missing.
