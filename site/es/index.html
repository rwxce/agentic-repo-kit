01 / El problema

Los agentes de código programan antes de planificar.

Hacen ingeniería a medida cuando ya existe un SDK o un import, se les escapan efectos secundarios entre sistemas, dan el trabajo por terminado cuando pasan tests con mocks y acumulan configuración inflada. Cada guardrail de este kit se añadió tras un fallo concreto en el código de un SaaS real.

3–6 de 18

efectos secundarios que se le escapan a cada planificador sin el protocolo. Ninguno consultó la documentación del proveedor.

~17 de 18

efectos secundarios encontrados con el pipeline completo.

Un protocolo escrito gana a un modelo más grande.

Un modelo más barato con el protocolo de planificación encontró casi tantos efectos secundarios como el más caro.

02 / Cómo funciona

No se escribe nada hasta que dices adelante.

Fase 0

Escanea y pregunta

Escanea el repo y muestra un menú de opciones: objetivo, familias, herramientas, estilo de código, profundidad y salida.

Modo

Nuevo o existente

Un proyecto limpio parte de las plantillas. Uno existente se examina antes más a fondo.

Repos existentes

Explora y mide

Lentes de descubrimiento, una decisión de estilo de código y un benchmark de una funcionalidad grande, todo en contextos limpios.

Fase 4

Propone con pruebas

Una propuesta con pruebas file:line para cada artefacto. Después espera tu luz verde.

Fase 5

Genera las PR

Subagentes en paralelo convierten la propuesta aprobada en pull requests.

Fase 6

Verifica de verdad

Tests, hooks disparados de verdad, ejecuciones de CI, el benchmark repetido y revisión adversarial.

/repo-bootstrap Pregunta qué quieres y después propone.
/repo-bootstrap quick Se salta el benchmark.
/repo-bootstrap audit Audita y mejora una configuración de agentes existente.

03 / Qué puede montar

Once familias. Elígelas todas o solo una.

Funciona con Claude Code, Cursor, Codex CLI, OpenCode, Copilot, Gemini CLI y otros, con rulesync como fuente única o con archivos nativos.

Reglas raíz

Plan antes del código, documentación primero, dependencias fijadas, verificación de principio a fin.

Agentes

Roles de orquestador, implementador y revisor, implementadores por dominio.

Skills

plan-feature, verify-integration, reflect, debugging, pr-review.

Hooks

Bloqueo de escrituras hacia fuera, control de comandos peligrosos, lint en cada cambio, comprobación previa de PR.

Tests de arquitectura

Sincronía entre registro y sistema de archivos, códigos únicos, paridad de i18n.

Lint propio

Límites entre capas, sin ciclos, pasarelas de SDK, tests junto al código.

CI

Sincronía de la configuración de IA, lint, typecheck y tests, comprobaciones de paridad, guarda de la política de ramas.

Automatizaciones

Preparación del espacio de trabajo, promoción de releases, control de versiones de las skills incluidas.

Permisos

Capas deny, ask y allow para la shell, los secretos y las acciones hacia fuera.

Registros

Registro de efectos secundarios, inventario del blueprint, variables de entorno.

Servidores MCP

Servidores oficiales separados entre prod y sandbox. Se proponen, nunca se instalan sin aprobación.

04 / Preguntas

Antes de ejecutarlo.

¿Funciona sin rulesync?

Sí. Elige “native files only” en la fase 0 y escribe directamente los archivos de .claude/ (o los de tu herramienta).

¿Reescribirá mi código?

Solo si eliges el refactor que preserva el comportamiento. Incluso entonces hace un plan aparte, con tests de caracterización primero y PR pequeñas.

¿Cuánto cuesta?

Una ejecución rápida son unos 60–120k tokens. El benchmark completo añade unos 200–300k. El benchmark es el paso que encuentra los huecos reales, así que se recomienda para repos que manejan dinero, autenticación o datos personales.

¿Instala servidores MCP?

No. Propone servidores oficiales con sus comandos de instalación y espera tu OK para cada uno.

O simplemente dilo: prepara este repo para agentes.
