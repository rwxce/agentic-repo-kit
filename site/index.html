01 / The problem

Coding agents start coding before they plan.

They build custom engineering when an SDK or import exists, miss cross-system side effects, call work done after mocked tests pass, and pile up bloated config. Every guardrail in this kit was added after a concrete failure in a real SaaS codebase.

02 / How it works

Nothing is written until you say go.

Phase 0

Scan and ask

Scans the repo and shows an options menu: goal, families, tools, code style, depth and output.

Mode

New or existing

A clean project starts from the templates. An existing one gets a closer look first.

Existing repos

Discover and benchmark

Discovery lenses, a code-style decision, and a big-feature benchmark run in fresh contexts.

Phase 4

Propose with evidence

A proposal with file:line evidence for every artifact. Then it waits for your go.

Phase 5

Generate PRs

Parallel subagents turn the approved proposal into pull requests.

Phase 6

Verify for real

Tests, real hook triggers, CI runs, benchmark re-runs and adversarial review.

/repo-bootstrap Asks what you want, then proposes.
/repo-bootstrap quick Skips the benchmark.
/repo-bootstrap audit Audits and improves an existing agent config.

04 / Questions

Before you run it.

Does it work without rulesync?

Yes. Choose “native files only” in Phase 0, and it writes .claude/ (or your tool’s) files directly.

Will it rewrite my code?

Only if you choose the behavior-preserving refactor. Even then it produces a separate plan, with characterization tests first and small PRs.

How much does it cost?

A quick run is roughly 60–120k tokens. The full benchmark adds roughly 200–300k. The benchmark is the step that finds real gaps, so it is recommended for repos that handle money, auth or personal data.

Does it install MCP servers?

No. It proposes official servers with their install commands and waits for your OK on each one.
